星探 · 四个把开关交回使用者的开源项目 第 14 版 / 共 16 版

本周开源趋势榜上，智能体编排层集中冒出四个项目。本报不给它们打分，只用三把筛子看：能不能自己托管、能不能看见每一步、能不能在半路按下停止公开报道。

Dexto：Truffle AI 放出的智能体框架，配置驱动，自带会话管理、工具编排与记忆，支持 50 多种模型并集成 MCP公开报道。它的取向是把「搭一个代理」变成写配置，而不是写胶水代码。对买方的意义是：编排逻辑变成可读的文件，审计时至少知道系统被允许做什么。

AgentSphere：把模型、工具与浏览器能力打包成可配置的智能体实例，强调感知—规划—执行—反馈的闭环，面向不太写代码的业务团队公开报道。闭环越完整，「谁在反馈那一步能改规则」就越要紧：一个能自己给自己打分的循环，如果没有外部中断点，跑偏也不会自己停。

Agent Relay：一份代码库里装了两个产品——给编码代理用的 Dev Boards（带任务看板），和给非技术用户用的 BeeZilla（从描述目标到草稿批准）公开报道。后者把「批准草稿」做成显式一步，是四个项目里唯一把停止键直接画进交互流程的。这一步看着笨，实际是本周主线在开源侧最干净的落地。

Dodaios v4.2.3：原名 Personal Jarvis，桌面端本地运行的超级代理，一个「主代理」拆活派给多个编码代理，支持并行跑测试与修复；对动作分风险等级，可能影响系统的改动要求用户批准；Apache 2.0，不需要自有账号、付费层或云设施，可接现有订阅或 Ollama 本地模型公开报道。项目也如实写了两处未完成：macOS 镜像尚未公证、Windows 安装包仍在等代码签名。把没做完的事写出来，比多写一句「企业级」可信。

三把筛子过完，结论并不整齐：能自己托管的四个都做到了；能看见每一步的，多数靠日志而非界面；能在半路按停的，只有两个写了明确机制。这正是本周「放开」的真实水位——工具已经足够让人把代理跑起来，但「跑起来之后怎么收」仍然主要靠使用者自己补。本报按公开仓库与趋势榜记录，未逐一安装复跑。

顺带说一句取舍。本周这类项目最容易被误读成「大厂的平替」，其实它们补的是不同的一格：大厂把模型与 API 放开，编排层决定这些能力以什么粒度、在什么权限下被调用。用不用它们，取决于你更在意开箱即用，还是更在意停止键握在自己手里。

锐评 本报评论员 · 针对本版星探

「批准草稿」这一步一点都不智能，却是四个项目里最值钱的设计。一个系统值不值得托付，常常不看它能自己走多远，看它在哪一步肯停下来等人。
