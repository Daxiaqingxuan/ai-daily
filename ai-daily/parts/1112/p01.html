模型没变，接口变了
今天这批更新，一条都没动模型

Google 把 A2UI 1.0厂商口径 推成首个稳定版：智能体不再只回文字，而是回一个可点的界面。同一天，SDK 给死循环装闸、云服务搬进本机。

  2. 02护栏进了 SDK：OpenRouter 四道闸，第三次重复调用就被拦下。
  3. 03账单落在接口：438 个 API 搬到本地、Python 3.10 被掐、联网按次计价。
本报编辑部　综合报道　2026-11-12

11 月 11 到 12 日这两天，发布列表长得吓人，但把模型那一栏遮住，剩下的东西反而更有信息量。Google 把 生成式 UI让智能体不只回一段文字，而是描述一张界面该有什么；由应用用自己的组件把它画出来。 协议推到 A2UI 1.0，官方称这是首个稳定版厂商口径；OpenRouter 在 Agent SDK 里加了四道防死循环的闸；AWS 把两百多款云服务的 438 个 API 模型搬进了本机模拟器；LangChain 全系把最低版本抬到 Python 3.11。没有一条是「模型变强了」。

本报把这层东西叫「接口」。它不负责聪明，只负责三件很具体的事：答案以什么形状交到人手上、失控的时候被谁兜住、升级的成本由谁付。过去两年大家盯的是参数、榜单和价格，因为那是模型的事；这一批更新说明，决定能不能真的用起来的，开始是接口的事。

A2UI 的设计里藏着一句很不客气的话：官方博客把今天的人机交互比作计算机还待在终端时代——能力够用，但几乎全靠文字公开报道。它的解法不是让模型把文字写得更漂亮，而是让模型只描述「该显示什么」，由 渲染器把界面描述变成真正可点的控件的那层程序。网页用 React、Angular、Lit，移动端用 Flutter、SwiftUI 与 Jetpack Compose。 拿应用自己的 原生组件应用自己写好的按钮、表单、图表，不是模型吐出来的一段 HTML。样式与交互由应用负责，模型只给内容。 画出来。数据与子组件在服务端绑定，敏感数值不进入模型厂商口径。一次回答从「一句话」变成「一张可以当场确认的表单」，这是形状的变化，不是分数的变化。

但同一份材料里也有一个不该被「1.0」盖过去的事实：企业要在 Gemini Enterprise 注册自己的 A2UI 智能体，文档写的仍是 0.9.1公开报道；Android 的 Jetpack Compose 渲染器还标着 alpha厂商口径。本报把这叫 协议版本漂移同一协议在博客、企业控制台、各平台渲染器上停在的版本号不一致。稳定版说的是协议，不等于每条落地路径都升级完了。：「1.0 是现行版」和「你现在能全线用上 1.0」是两句话。第 03 版把六个渲染器的成熟度列成表，第 12 版再算升级要付的代价。

另一侧的更新方向更朴素：给会自己跑的东西装闸。OpenRouter 说智能体最常见的失控不是「做坏事」，而是反复调用一个失败的工具——每一轮都把整段对话重发一遍，越跑越贵，放一夜可能烧掉几千美元公开报道。它加的四道闸里，没有一道在改模型，全在改调用层。第 05 版拆这四道闸，第 06 版给一份「接口变更五问」。

所以本期不写「谁又刷新了榜单」。今天真正该记下来的是：当模型够用之后，竞争从「它会不会」移到「它怎么把结果交出来、出错了谁兜、换版本谁付钱」。这三件事都不在权重里，却全在你每天要维护的代码里。
