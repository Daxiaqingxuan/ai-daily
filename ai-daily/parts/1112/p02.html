本报一直有个不太受欢迎的判断：一个系统好不好用，多半不取决于它最聪明的那一刻，而取决于它笨、它卡住、它要跟别的系统打招呼的那些时刻。这两天所有值得写的更新，都发生在这些时刻里。

第一层是输出。文字是一种非常便宜的界面：模型随便说，人自己猜。它便宜到让人忘了代价——要确认一个日期、一个金额、一个选项，读者得把整段话再读一遍，再从里面挑出能点的东西。生成式 UI 把这一步搬回应用：模型只描述要显示什么，按钮和表单由应用画。这不是体验优化，是把「确认」这件事从自然语言里赎回来。它同时带来一个副作用：模型不再接触那些敏感数值，责任边界跟着清楚了。

第二层是护栏。一个会自己调用工具的循环，最危险的时候不是它想做坏事，而是它太执着：工具失败、参数没变、再来一次。每重试一轮就把整段对话重发一遍，成本逐轮抬高，而循环本身没有任何「停」的信号。四道闸——检测、重复规则、步数上限、成本上限——听上去毫无想象力，但它们安装在正确的位置：不是教模型别犯傻，是让系统不可能无限犯傻。前者靠权重，后者靠代码，可靠性差着一个数量级。

第三层是成本与兼容。把 438 个 API 搬进本机，省的不是钱，是「为了测一个分支去开一个云账号」这道手续；把最低版本从 3.10 抬到 3.11，动的不是能力，是几万条 CI 流水线；把联网搜索标成每千次查询 7 美元，改变的不是搜索质量，是智能体能不能被放进有预算的产品里。这三条都是账，不是技术突破，但它们决定技术会不会被真的用上。

把这三层放在一起，本期的主线才成立：模型没变，接口变了。这不是说模型不重要，而是说当能力越过某个门槛之后，边际收益开始从「再强一点」转向「更稳地交出去」。过去我们评价一份发布，问的是它多了几个百分点；现在更该问三句：答案长什么样、出错谁兜底、升级谁付钱。

本报也要给这句话划个边界。接口层热闹，不代表底层停滞；今天同时有形式化验证、物理世界模型、端侧小模型在推进（见第 09、11 版）。但那些进展要变成生产环境里的东西，仍然要先穿过这层接口。一个再强的模型，如果只能用一段含糊的文字把结果丢回来，读者照样得自己猜。所以本期不把「接口」写成配角，它就是这两天的主角。
