A2UI 1.0 的核心不是「更好看的回答」，而是把责任切开：智能体只负责描述内容与意图，应用负责画、负责交互、负责数据绑定。协议以 Apache 2.0 许可开源厂商口径，由 Google 创建、CopilotKit 与社区参与贡献。

1.0 新增了什么。最要紧的是 双向函数调用厂商口径：界面上的控件可以反过来向智能体发起一次调用，例如航班或预约选择器当场核查余位，而不是把「请确认」写进文字里等人回复。另外补了无障碍支持与附加元数据的扩展。官方列出的智能体 SDK 从 Python 扩到 TypeScript 与 Dart，官方称可用于生成技能、翻译消息与纠错厂商口径。

渲染器是另一半，成熟度并不齐。网页端有 React、Angular、Lit；Flutter 覆盖移动端、网页与桌面；iOS 用 SwiftUI；Android 用 Jetpack Compose，而官方明确说 Compose 渲染器仍是 alpha、1.0 支持「即将到来」厂商口径。网页与 Flutter 渲染器也能跑在 MCP 应用内，所以同一条信息流可以出现在支持 MCP 应用的助手里，例如 Claude 与 Gemini。

安全设计值得单独说。智能体不产出可直接执行的界面代码，只描述「要显示什么」；每个应用用自己的组件绘制，数据与子组件在服务端完成绑定，敏感数值不进入模型厂商口径。这同时解决了两件事：样式不会被模型带偏，以及财务数字不必经过上下文窗口。代价是应用方得自己实现渲染器——开源 SDK 把这件事的成本降下来了，但没降到零。

本报保留一个问号。官方博客写「1.0 已是现行版本」，企业控制台仍写 0.9.1，Android 渲染器还是 alpha公开报道。这三句话同时为真，说明「协议稳定」与「全平台稳定」不是一回事。读者若按 1.0 去排期，最好先确认自己走的是哪条路径；第 12 版把这类成本列得更细。
