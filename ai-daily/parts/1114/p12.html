工具链 · 给智能体装表、装闸、装账单 第 12 版 / 共 16 版

工具这一层的更新今天格外务实：能看、能控、能算出花了多少钱，三件事分别对应调试、权限与成本。

能看。Chrome 团队的 chrome-devtools-mcp 当日登上 GitHub 趋势榜首位，让智能体直接检查与控制 Chrome；NiCE 的 Cognigy 新版本加入逐步追踪，并可同时模拟最多 10 个版本做对比公开报道。智能体一旦会自己连点十几步，「每一步做了什么」就从调试便利变成了必需。

能控。AWS 给出在 Fargate 上用 LiteLLM 搭自助式 LLM 网关的做法：开发者只拿一把 API Key，平台侧按人做成本上限与配额隔离厂商口径。这是把「准不准进」写进基础设施——与第 08 版的准入线是同一件事，只是执行方换成了平台团队。

能算账。AWS 另一篇指南把 Amazon Bedrock 上的真实每任务成本拆成 4 个隐藏驱动，并建议用缓存、路由与输出上限压成本，再用人工基线与留出测试证明智能体的投入产出厂商口径。本报特别记下「人工基线」这一项：没有对照组的效率提升，无法证伪。

同日的小更新还有：Kiro 的 AI 编码工具上线 Android；Google AI Pro / Ultra 订阅者可以在 AI Studio 里领月度云额度；Vercel UI SDK 让智能体把界面拼成可访问组件公开报道。三项都在把「能不能用」变成「用多少、谁付钱」。

锐评 本报评论员 · 针对本版

调试、权限、账单，是智能体从演示走到生产要补的三张表。模型能力决定它能不能做，这三张表决定敢不敢让它做。
