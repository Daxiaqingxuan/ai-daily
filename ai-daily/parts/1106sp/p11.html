昨天那 1.56TB 放出来之后，问得最多的不是「它有多强」，是「我这台机器能不能跑」。本版把三种最常被问到的配置算成同一张表，成本口径统一按「每百万输出 token」，含折旧与电费（自建）或按时计价（云）。

为什么第一行有两个价格。因为显存只有 640GB，模型要 390GB，剩下的空间决定了你能同时塞几路请求。单流的时候显卡 70% 的时间在等权重从显存里读出来，算力是闲着的；批到 32 路，同样一次读权重能算 32 份，成本被摊薄 20 倍。「自己部署更便宜」这句话，只有在你能凑出并发时才成立——而绝大多数团队的请求量，凑不出这个并发。

第二行为什么劝你别买。1.56TB 的 Q4 是 390GB，4 张 5090 加起来 128GB，缺口 262GB 只能靠内存填补。内存带宽是显存的十分之一左右，每生成一个 token 都要把没装下的专家从内存搬一遍，于是速度掉到 38 tok/s（6 并发），单 token 成本反而是云端的五倍多。这笔钱花下去，你得到的是一个「证明了自己不该这么干」的实验。

第四行为什么才是正解。如果你要的是「本地、离线、数据不出门」，那目标从来不是跑最大的模型，而是跑一个「够用且装得下」的模型。32B 级模型 Q4 后约 19GB，单卡 24GB 装得舒服，120 tok/s，成本 ￥3.5/百万——比最便宜的 API 还便宜一个数量级，代价是能力差两档。这个交换是否值得，取决于你的任务容错率，而不取决于榜单。

锐评 本报评论员 · 针对本版这张账

这张表最想说的是：「开源权重」和「本地可用」之间隔着一个数量级的成本。媒体喜欢写「人人都能跑」，实际是「有 640GB 显存的人能跑」。真正被低估的是第四行——一个 32B 模型装在 24GB 显卡上，￥3.5 一百万字，离线、可控、不需要求人。对个人开发者来说，这可能是今年性价比最高的一件事，而它一点都不性感。
