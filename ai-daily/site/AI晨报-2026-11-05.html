Kimi K3.1 Pro 权重落地
1.56TB，开源第一次够到终端

Terminal-Bench 4.0 拿到 65.7，只比 Claude Opus 5.5 低 0.7 分；96 个文件、1.56TB——能下载和能跑起来，是两件事。

本报编辑部　综合报道　2026-11-05

权重是十一月五日零点放出来的。月之暗面按 10 月 23 日发布时的承诺，在 Hugging Face 上开放了 Kimi K3.1 Pro 的模型文件：总参数 2.8 万亿，每次推理激活约 1040 亿，上下文约 100 万 token，能读图。模型卡里写得很直白——它是在 K3 的基础上继续训练出来的，把一部分注意力层换成了更省资源的稀疏注意力，长文本因此变便宜。

成绩单有两处值得看。第一处是 Agent Arena：在约 1.8 万次真实用户智能体会话上，它拿下开放权重模型第一、全部参评模型第 13（另一份快照记为第 14），净改进率 +5.29%，第二名小米 MiMo-V2.6-Pro 是 +2.68%，DeepSeek-V4.1-Flash +2.37%，GLM-5.3 +1.09%。这个榜不看人工盲测投票，而是从会话里抠信号：用户说「搞定」算成功，「??」和「重来」算负反馈，敲错的 shell 命令算可靠性崩盘。它的 Bash 可靠度从 K3 时代的 −4.5%（倒数第 13）升到 +7.9%，开放模型里断层第一。

第二处是 Terminal-Bench 4.0：65.7 分。同一张表上 GPT-6 Astra 是 58.2，Claude Opus 5.5 是 66.4。也就是说，在「给你一个终端，把这件事做完」这种最像干活的测试上，开放权重和闭源旗舰的差距已经被压到 1 分以内——半年前这个差距还是两位数。

但文件本身是个门槛。权重共 96 个文件，合计约 1.56TB；想在本地跑，先要有一台装得下它的机器，再要有撑得住 100 万上下文的显存。许可证也不是纯自由：拿它对外提供 API 一类服务、且年收入超过 2000 万美元的公司，需要先与月之暗面另签协议。换句话说，开源的是权重，不是算力，也不是商用豁免。

把这件事放回本周的坐标里看，脉络就清楚了：昨天 DeepSeek 把 Super-agent 原型开源，今天月之暗面把底座权重开源，两家都在用「开放」换开发者心智。而真正决定这套东西能不能落地的，是昨天那份漏洞报告里的数字——一次自动扫描找出 948 个能拿 root 的 Linux 提权漏洞，API 花了 121 万美元。能力越强，账单越像工程预算，不像订阅费。

开放权重这一年，赢家不是「开源阵营」

本报评论员　2026-11-05

今天有两件事同时发生：月之暗面把 2.8 万亿参数的权重放上 Hugging Face，OpenAI 把一份「AI 自动找出 948 个 root 漏洞」的报告放上官网。一件讲能力如何被复制，一件讲能力如何被计价。把它们并排放，会发现这一年关于「开源还是闭源」的争论，问错了问题。

错在哪？我们把「开放权重」当成了阵营归属，于是每次榜单刷新都要宣布一次胜负。可今天这个 65.7 分说明的是另一件事：能力正在变成可采购的日用品，差异化从「模型多强」挪到了「谁能让它稳定干活」。同样一个 K3.1 Pro，放在一个会写 postcondition 的 harness 里，和放在一个「点击返回成功就记一笔」的循环里，产出差的是一个数量级——这一点，第 13 版掘金那篇实操写得很清楚：工具层返回 success，后端一个请求都没收到。

模型负责意图，外壳负责可证实的状态迁移。这句话今年被反复验证，但很少有人愿意承认它对产品意味着什么。

意味着三件事。第一，选型的重心从参数转向工具链接入。Google 今天把 Android Studio 的符号、预览、崩溃报告开放给 40 多款第三方智能体，连自家 Antigravity 都不给特权，就是在承认：IDE 的护城河不再是「绑谁的模型」，而是「上下文给得多细」。

第二，成本的形状变了。同一次 12 步工具调用，走 Claude Sonnet 5.5 是 0.48 美元，走 DeepSeek Flash 峰价是 0.068 美元，走 GPT-6 Astra 是 2.40 美元（口径见第 12 版）。差距 35 倍。当能力拉平，这 35 倍就是产品能不能成立的分界线——不是「要不要用 AI」，而是「这个功能按次收费收得回来吗」。

第三，责任开始有价格。苹果在 10-K 里把「智能体以不可预测方式行事」写成风险因素；五家美国大行封堵第三方智能体访问客户账户；国内 155 款应用拒绝手机助手的屏幕自动化。这些不是技术问题，是「出事了谁签字」的问题。而今天所有开源公告里，没有一份回答这个。

所以本报的判断是：这一年真正的赢家不是开源阵营，也不是闭源阵营，而是那些把「可验证」做成产品的人——FlashProve 用零知识证明回答「这段输出是不是你付费的模型」，Dify 1.17 用统一追踪回答「这一步到底发生了什么」，掘金那篇实操用 postcondition 回答「这次点击到底成没成」。它们解决的是同一类焦虑：我不需要它更聪明，我需要它别骗我。

至于 1.56TB 的权重，它的意义要等到明年才看得清。今天它证明的是「开放权重可以摸到前沿」，而不是「你我可以摸到前沿」。把这两件事分开，讨论才有意义。

网友锐评 Hacker News 讨论串，针对本报社论观点

「可验证被做成产品」听着对，但顺序反了：先有能跑起来的业务，才有资格谈验证。我所在的小团队去年就在纠结要不要上审计日志，最后发现真正卡住我们的是模型在第 7 步把价格算错了，而不是没人签字。你们把「责任」当主线，是因为你们不用为转化率负责。本报回应：这个反驳成立一半——验证确实不该先于业务，但第 7 步算错价格这种事，恰好只能靠事后校验发现，靠模型自己「觉得对」永远发现不了。

终端执行

65.7 分意味着什么：开放权重第一次够到「自己把事做完」

Terminal-Bench 4.0 测的不是答题，是给一个终端、让模型自己把任务做完：装依赖、读报错、改命令、验结果。Kimi K3.1 Pro 拿 65.7，GPT-6 Astra 58.2，Claude Opus 5.5 66.4。

三个数字放一起，结论不是「开源赢了」，而是「终端操作这件事已经商品化」。一年前这个榜单上 40 分就算好成绩，因为模型不会读报错。它变强的顺序很值得注意：先学会不把命令敲错（Bash 可靠度 +7.9%），再学会被骂了能掉头（可引导性 +6.5%）。

代价也在同一张模型卡上：要跑满 100 万上下文，显存按总量算，MoE 省的是算力不是显存。

图像生成

Images 2.6：出图快 50%，第一次能一步出 GIF

OpenAI 的新图像模型向 ChatGPT 与 Codex 全部档位开放。官方口径是速度提升 50%，ChatGPT 里可一步生成 GIF，能调播放速度、逐帧改。

API 侧拆成两个模型：Flare 求快，低画质最快约 6 秒一张；Sunburst 求精，多轮修改时人物与产品更不容易走样。开发者可以在图上圈出要改的位置，导出 SVG。

真正的数字是这个：每周在 ChatGPT、Codex 和 API 里生成的图有 40 亿张，9 月还是 30 亿——六周涨三分之一。图像已经不是「创作功能」，是流量基础设施。

可验证推理

FlashProve：不开源权重，也能证明「这话是它说的」

Anthropic 开源研究原型 FlashProve。提供方先为一组权重发布一个不公开权重的加密「承诺」，用来钉住这组参数；生成回复后再附一份证明文件。

用户拿到承诺、输入、回复、证明四样东西，在自己的 CPU 上就能验，不需要权重，也不需要重跑整个模型。这解决的是一个很实际的问题：模型 API 说「这是 Opus 答的」，你怎么信？

目前是研究原型，不是产品。但方向明确：把「信任」从服务条款里拿出来，变成一份可以本地校验的文件。

锐评 本报评论员 · 针对本版三个能力进展

三件事看起来不相关，其实都在给同一件事补零件：让「模型说的话」变成「可核对的事实」。65.7 分是可复现的跑分，40 亿张是可统计的产出，FlashProve 是可本地验证的证明。反倒是厂商最爱讲的「智能涌现」一个字都没提。给读者的判断标准：一个能力公告如果给不出第三方能重跑的数字，它就不是能力公告，是宣传。

逆向 · 复刻

Craft Anything：把「看懂一个软件」做成四步流水线

storytold/craft-anything　Rust　MIT 或 Apache-2.0（二选一）　0.1.0（10/31）→ 0.2.0（11/1）　约 2.2K 星

它做什么你给它一个目标（网址、桌面应用、游戏），写一句「照着这个做一个」，它先以访客身份把原件研究一遍，再让本机的编码智能体按证据建一个新项目，最后逐页比对、差在哪儿直接说。它不是网页克隆器——它带了 300 多个逆向工具，能拆原生程序、.NET、Java、Android、Electron、固件、抓包与游戏文件。

怎么工作四步固定流程：研究原件 → 建新项目 → 与原件比对 → 打开试玩，不符合就回到第三步再改。两种模式划得很清楚：净室（默认）什么都不读内部，只用访客看得见的东西——截图、可见文本、量出来的尺寸、颜色、字体、打开过的菜单；深挖才启用引擎读代码与文件、看页面 JavaScript 的启动过程，官方定位是「私人用途」。

craft-anything-cli doctor            # 先自检：编码 agent、引擎、系统依赖缺什么
craft-anything-cli rebuild https://example.com "Recreate this website"
craft-anything-cli mcp               # 把全部工具挂成 MCP，任何 agent 都能调

数字13 个 crate、约 25.9 万行 Rust；923 个测试通过（作者 10 月 23 日基线审计）；发布两天 2794 星、444 fork，四天后 9388 星、1550 fork。项目自标「早期 alpha」，这是它最诚实的部分。

为什么这条和你有关你在写 MonitorWidget，一定遇到过「某个软件的悬浮窗怎么画的、怎么吸边、怎么不抢焦点」这类问题。以前只有两条路：扒源码，或者对着截图猜。它给的第三条是把「看懂」变成留痕的证据——这恰好也是你自己做监测器时最缺的一环：你怎么证明采集到的是真温度，而不是缓存里的旧值。

会卡住的地方：构建侧是最不成熟的一段。必须本机装好并登录 Claude Code，Codex 适配器「已建好但未在真实安装上验证」；网站检查只覆盖三种屏幕宽度，应用与游戏的行为级检查只算「部分到位」；本地模型目前跑不通，得走 API key 或其他编码 agent，而这两条也只算部分可用。

本地推理 · 显存

Strata：1250 亿参数的模型，塞进 12GB 显卡

Niko1221/Strata　推理调度　模型：Qwen3.8-Flash-Next（125B MoE）　显存 12GB 起步

它做什么让一张 12GB 的游戏显卡跑起一个 1250 亿参数的 MoE 模型。不是「能加载」，是能连续出字：RTX 5070（12GB）在 Q2_0 量化下约 94 token/s，RTX 3090（24GB）约 100–140。

怎么工作这套模型内部有 24576 个「专家」，每生成一个词只挑其中 10 个干活。既然如此，就不必整机装下：显卡只留最常被点名的几千个专家（热菜放灶台），内存装全部（其余囤储物间），CPU 处理剩下的，SSD 里放一张大查找表。再叠一层「先猜后验」：小助手先猜接下来几个词，大模型一次验完，答案不变，速度 1.6–1.8 倍。长 prompt 按最多 8192 token 分块读，吞吐超过 1000 token/s。

门槛与数字显存 12GB 起步、内存 32GB、磁盘留 80GB、模型下载约 70GB。有人用 RTX 4090 + 128GB DDR5 + 7950X3D 实测到 124 token/s。

代价（这条最关键）为了塞得下，量化压到 Q2 / IQ2 一档。有人拿 50 张图做视觉定位测试，与 llama.cpp 对比，Strata 的中位误差 154.8 像素、平均 168.8 像素，明显更差。省下来的显存，账单会在精度上寄回来。

会卡住的地方：Q2 级别量化对需要精确坐标、精确数字的任务伤害最大——你要是拿它做表格识别或 UI 定位，误差会直接毁掉下游逻辑。它适合的是「聊天、写草稿、粗读长文」，不是「照着截图点按钮」。

vercel-labs/agent-desktop　Rust　给任何智能体提供桌面「动手能力」　约 7.8K 星

它做什么把「计算机使用」封装成命令行工具：智能体能打开应用、点界面、执行桌面级任务。区别在于它不靠截图猜坐标，而是走系统无障碍树（accessibility tree），让每个可操作元素都有稳定引用。

为什么这条路更稳纯视觉方案在密集列表页上命中率低得可怜：一屏内容喂进去几十万 token，还要赌模型能从像素里认出哪个是「点赞」。换成元素编号后，定位可靠性至少高一个数量级，代价是要做可见性过滤与截断——本质是在赌「模型不需要看到全部也能做对」。

数字与口径今日新增约 3792 星，七日 +6.0K。它是 Vercel Labs 出品，Rust 实现，跨平台。这些都是榜单快照，不是本报实测。

为什么这条和你有关你在写一个覆盖在其他窗口之上的悬浮窗，还设了 WS_EX_LAYERED。这类窗口在无障碍树里往往是「不存在」的——读屏软件看不见它，智能体也看不见它。这既是保护（不会被误点），也是限制（你没法用 agent 自动测它）。要做端到端测试，得给它补一条可访问路径。

三个项目凑在一起，恰好说明「智能体落地」卡在哪：不是模型不够聪明，是它看不见、装不下、验不了。Craft Anything 解决「看不见内部」，Strata 解决「装不下权重」，agent-desktop 解决「看不清界面」。它们给的都是工程答案，不是模型答案。判断一个 agent 项目值不值得跟，就看它有没有正面回答这三件事之一；只会调 API 的，一律归到「提示词工程」。

思路 · 六次问题转换 第 06 版 / 共 15 版

本版不讲参数，只讲一件事：每个项目都在把一道难题，换成一道更容易的题。看懂换法，比记住功能有用。

说人话

什么叫换掉一道题？自行车原来的链条总掉，工程师没去研究「怎么让链条不掉」，而是把链条换成皮带——问题没解决，是问题消失了。下面六个项目，干的都是这件事。

01Craft Anything

把「读懂别人的代码」换成「像访客一样取证，再按证据重建」

原题想复刻一个软件，常规做法是读它的源码。但压缩过的代码读不动，.NET 与 Electron 还隔着壳；猜出来的版式又没法验证对不对。隐藏假设是：你必须先「理解」，才能「重建」。

换法放弃理解，改成取证：默认净室模式只采集访客能看见的东西——截图、可见文本、量出来的尺寸与色值、打开过的菜单，全部存进 capture/。然后让编码 agent 按证据写新项目，写完立刻与原件逐页比对，把差异写成 checks/ 里的记录。理解被替换成了「证据 + 差异」这一对可复核的产物。

代价放弃了「内部逻辑」这一层：拿不到原件的算法、状态机与私有协议，只能重建外观与可见行为。所以它对「界面型」目标有效，对「逻辑型」目标基本无效；而且必须有一个已登录的编码 agent 在场，没有它连第一步都走不完。

可抄走凡是「要理解一个黑盒」的任务，都先把它拆成「取证 → 重建 → 比对」三段，并强制每段留下文件；没有留下证据的「理解」，等于没理解。

02Strata

把「把模型装进显存」换成「把显存当缓存，把内存与 SSD 当仓库」

原题本地跑大模型的默认思路是「装得下才能跑」：权重几 GB，显存就要几 GB，装不下就量化、再装不下就换小模型。隐藏假设是：每次推理都要用到全部权重。

换法MoE 模型每次只激活少数专家，于是把「全部驻留」换成「分层驻留」：最热的几千个专家常驻显卡，全量放内存，冷门专家交给 CPU，SSD 存一张查找表；再叠投机解码，小模型先猜、大模型一次验完。显存从「容量上限」变成了「命中率缓存」。

代价冷门专家一旦被点名就要走内存或 CPU，延迟抖动明显；为了压进 Q2 一档，精度损失会在需要精确数值的任务上放大——视觉定位中位误差 154.8 像素就是账单。它换来的是吞吐，不是质量。

可抄走凡是「数据总量远大于可用内存」的系统，都别问「怎么装下」，先问「最近用到的占多少」；把内存当缓存设计，命中率就是你的性能上限。

03agent-desktop

把「看懂屏幕」换成「查一张带编号的清单」

原题让智能体操作桌面，最直觉的做法是给截图、让它输出点击坐标。隐藏假设是：界面对模型来说是一张图。可一屏密集列表几十万 token，模型还得从像素里认出哪个是「点赞」，猜偏几像素就点到旁边的空白。

换法改读系统无障碍树：每个可操作元素有类型、名字、状态和稳定引用，模型只需要说「点 ref=47」，不需要说「点 (812, 436)」。快照要做可见性过滤与截断，但元素编号的稳定性远高于像素坐标。

代价只对愿意暴露自己的应用有效。自绘界面、老式 Win32 控件、设了 WS_EX_LAYERED 的覆盖窗，树里根本没有它——这类目标只能退回视觉方案。另外截断本身是在赌「模型不需要看到全部」，赌错就漏元素。

可抄走凡是「让程序操作界面」的需求，先查目标有没有结构化接口（无障碍树、API、DOM），有就别用坐标；坐标方案只作为最后兜底。

04dsh-Go

把「智能体跑在服务器上」换成「智能体跑在口袋里」

原题Super-agent 类系统的隐含前提是「有一台常开的机器」：进程要一直在、会话要连续、任务要能在后台推进。隐藏假设是：你手边那台设备跑不了。

换法把一个内置 Linux 环境塞进 Android 应用，DSH（DeepSeek Harness）引擎直接在手机上原生跑，不 Root。常驻这件事因此从「服务器运维问题」变成「手机别没电问题」——同一台设备既是终端也是执行器。

代价手机是会被杀进程的：后台限制、省电策略、系统更新都可能中断长任务；算力与散热也决定了它只能跑轻任务。它换来的不是性能，是「随身」。

可抄走凡是依赖「常驻进程」的设计，都要先问一句：能不能把常驻下沉到用户已经在随身携带的设备上？能，运维成本就变成了电量成本。

05Kimi K3.1 Pro

把「把每个 token 都算一遍」换成「只算被点名的那些」

原题要把上下文做到 100 万 token，标准做法是扩大注意力窗口，代价是计算量随长度平方增长，长文本立刻变得又慢又贵。隐藏假设是：每个 token 都要和每个 token 互相看一遍。

换法在 K3 基础上继续训练，把一部分注意力层换成稀疏注意力，只让必要的连接参与计算；配合 MoE 每次只激活约 1040 亿（总量 2.8 万亿），把「长上下文」的成本压到可商用。Bash 可靠度 +7.9%、可引导性 +6.5% 是这条路线在智能体任务上的直接收益。

代价稀疏意味着「可能漏看」：需要精确回溯某个细节时，稀疏注意力不如全注意力稳。另一个代价在权重之外——1.56TB 的文件，让「开源」在事实上只对云厂商和大公司成立。

可抄走凡是「规模一大就贵得离谱」的系统，别急着加机器，先问「这次真的需要看全部吗」；把「全量计算」换成「按需命中」，是这一代模型降本最通用的手法。

06Google BYOA

把「让开发者用我的模型」换成「把我的上下文接给任何模型」

原题IDE 厂商的默认打法是绑定自家模型：工具链、补全、重构都指向自家模型，开发者想换就得搬家。隐藏假设是：护城河在模型归属上。

换法反着做：把项目结构、构建配置、符号解析、Compose 预览、模拟器、Logcat 做成开放接口，40 多款遵循 ACP 协议的智能体都能接进来，自家 Antigravity 不享受特权。护城河从「模型」挪到「上下文与工具链接入的深度」。

代价放弃模型层的分成与锁定，收益要靠生态规模换；同时要承担兼容成本——40 多个 agent 的行为差异，最终都会变成支持工单。另外「变更审查」这类功能意味着责任边界变模糊：智能体改的代码出了问题，算谁的？

可抄走凡是平台型产品，都该问一句：我的护城河是「用户离不开我的模型」，还是「用户离不开我提供的上下文」？前者会被价格战打穿，后者越用越深。

六次交换的共同点

六次交换做的其实是同一件事：把「必须理解全部」换成「只需命中关键」。Craft Anything 不读懂代码，只留证据；Strata 不装下全部权重，只驻留热专家；agent-desktop 不看整张屏幕，只查编号清单；dsh-Go 不依赖服务器，只用随身设备；K3.1 不算每个 token，只算被点名的；Google 不锁定模型，只开放上下文。它们都放弃了「完整性」，换来了「可运行」。

倒过来读，就是一份选型清单：要复刻别人的软件→Craft Anything；要在小显卡上跑大模型→Strata；要让 agent 操作桌面→agent-desktop；要一个随身常驻的智能体→dsh-Go；要长上下文还不能太贵→K3.1 这类稀疏+MoE 路线；要接多个 agent 而不是绑一个→找有开放协议（ACP/MCP）的底座。

锐评 本报评论员 · 针对「怎么看一个项目」

看项目别先看功能列表，先找它「放弃了什么」。一份 README 里如果找不到「不适合谁」，那它大概率还没被真实使用过。Craft Anything 明说本地模型跑不通，Strata 明说 Q2 会掉精度，agent-desktop 明说自绘界面读不到——这三句「不行」，比它们所有「很行」都值钱。判断一个项目能不能进你的技术栈，就看它的失败边界写得够不够具体。
