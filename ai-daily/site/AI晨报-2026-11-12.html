模型没变，接口变了
今天这批更新，一条都没动模型

Google 把 A2UI 1.0厂商口径 推成首个稳定版：智能体不再只回文字，而是回一个可点的界面。同一天，SDK 给死循环装闸、云服务搬进本机。

本报编辑部　综合报道　2026-11-12

11 月 11 到 12 日这两天，发布列表长得吓人，但把模型那一栏遮住，剩下的东西反而更有信息量。Google 把 生成式 UI让智能体不只回一段文字，而是描述一张界面该有什么；由应用用自己的组件把它画出来。 协议推到 A2UI 1.0，官方称这是首个稳定版厂商口径；OpenRouter 在 Agent SDK 里加了四道防死循环的闸；AWS 把两百多款云服务的 438 个 API 模型搬进了本机模拟器；LangChain 全系把最低版本抬到 Python 3.11。没有一条是「模型变强了」。

本报把这层东西叫「接口」。它不负责聪明，只负责三件很具体的事：答案以什么形状交到人手上、失控的时候被谁兜住、升级的成本由谁付。过去两年大家盯的是参数、榜单和价格，因为那是模型的事；这一批更新说明，决定能不能真的用起来的，开始是接口的事。

A2UI 的设计里藏着一句很不客气的话：官方博客把今天的人机交互比作计算机还待在终端时代——能力够用，但几乎全靠文字公开报道。它的解法不是让模型把文字写得更漂亮，而是让模型只描述「该显示什么」，由 渲染器把界面描述变成真正可点的控件的那层程序。网页用 React、Angular、Lit，移动端用 Flutter、SwiftUI 与 Jetpack Compose。 拿应用自己的 原生组件应用自己写好的按钮、表单、图表，不是模型吐出来的一段 HTML。样式与交互由应用负责，模型只给内容。 画出来。数据与子组件在服务端绑定，敏感数值不进入模型厂商口径。一次回答从「一句话」变成「一张可以当场确认的表单」，这是形状的变化，不是分数的变化。

但同一份材料里也有一个不该被「1.0」盖过去的事实：企业要在 Gemini Enterprise 注册自己的 A2UI 智能体，文档写的仍是 0.9.1公开报道；Android 的 Jetpack Compose 渲染器还标着 alpha厂商口径。本报把这叫 协议版本漂移同一协议在博客、企业控制台、各平台渲染器上停在的版本号不一致。稳定版说的是协议，不等于每条落地路径都升级完了。：「1.0 是现行版」和「你现在能全线用上 1.0」是两句话。第 03 版把六个渲染器的成熟度列成表，第 12 版再算升级要付的代价。

另一侧的更新方向更朴素：给会自己跑的东西装闸。OpenRouter 说智能体最常见的失控不是「做坏事」，而是反复调用一个失败的工具——每一轮都把整段对话重发一遍，越跑越贵，放一夜可能烧掉几千美元公开报道。它加的四道闸里，没有一道在改模型，全在改调用层。第 05 版拆这四道闸，第 06 版给一份「接口变更五问」。

所以本期不写「谁又刷新了榜单」。今天真正该记下来的是：当模型够用之后，竞争从「它会不会」移到「它怎么把结果交出来、出错了谁兜、换版本谁付钱」。这三件事都不在权重里，却全在你每天要维护的代码里。

本报一直有个不太受欢迎的判断：一个系统好不好用，多半不取决于它最聪明的那一刻，而取决于它笨、它卡住、它要跟别的系统打招呼的那些时刻。这两天所有值得写的更新，都发生在这些时刻里。

第一层是输出。文字是一种非常便宜的界面：模型随便说，人自己猜。它便宜到让人忘了代价——要确认一个日期、一个金额、一个选项，读者得把整段话再读一遍，再从里面挑出能点的东西。生成式 UI 把这一步搬回应用：模型只描述要显示什么，按钮和表单由应用画。这不是体验优化，是把「确认」这件事从自然语言里赎回来。它同时带来一个副作用：模型不再接触那些敏感数值，责任边界跟着清楚了。

第二层是护栏。一个会自己调用工具的循环，最危险的时候不是它想做坏事，而是它太执着：工具失败、参数没变、再来一次。每重试一轮就把整段对话重发一遍，成本逐轮抬高，而循环本身没有任何「停」的信号。四道闸——检测、重复规则、步数上限、成本上限——听上去毫无想象力，但它们安装在正确的位置：不是教模型别犯傻，是让系统不可能无限犯傻。前者靠权重，后者靠代码，可靠性差着一个数量级。

第三层是成本与兼容。把 438 个 API 搬进本机，省的不是钱，是「为了测一个分支去开一个云账号」这道手续；把最低版本从 3.10 抬到 3.11，动的不是能力，是几万条 CI 流水线；把联网搜索标成每千次查询 7 美元，改变的不是搜索质量，是智能体能不能被放进有预算的产品里。这三条都是账，不是技术突破，但它们决定技术会不会被真的用上。

把这三层放在一起，本期的主线才成立：模型没变，接口变了。这不是说模型不重要，而是说当能力越过某个门槛之后，边际收益开始从「再强一点」转向「更稳地交出去」。过去我们评价一份发布，问的是它多了几个百分点；现在更该问三句：答案长什么样、出错谁兜底、升级谁付钱。

本报也要给这句话划个边界。接口层热闹，不代表底层停滞；今天同时有形式化验证、物理世界模型、端侧小模型在推进（见第 09、11 版）。但那些进展要变成生产环境里的东西，仍然要先穿过这层接口。一个再强的模型，如果只能用一段含糊的文字把结果丢回来，读者照样得自己猜。所以本期不把「接口」写成配角，它就是这两天的主角。

能力底座 · 一个协议，六个渲染器 来源 · 官方第 03 版 / 共 16 版

A2UI 1.0 的核心不是「更好看的回答」，而是把责任切开：智能体只负责描述内容与意图，应用负责画、负责交互、负责数据绑定。协议以 Apache 2.0 许可开源厂商口径，由 Google 创建、CopilotKit 与社区参与贡献。

1.0 新增了什么。最要紧的是 双向函数调用厂商口径：界面上的控件可以反过来向智能体发起一次调用，例如航班或预约选择器当场核查余位，而不是把「请确认」写进文字里等人回复。另外补了无障碍支持与附加元数据的扩展。官方列出的智能体 SDK 从 Python 扩到 TypeScript 与 Dart，官方称可用于生成技能、翻译消息与纠错厂商口径。

渲染器是另一半，成熟度并不齐。网页端有 React、Angular、Lit；Flutter 覆盖移动端、网页与桌面；iOS 用 SwiftUI；Android 用 Jetpack Compose，而官方明确说 Compose 渲染器仍是 alpha、1.0 支持「即将到来」厂商口径。网页与 Flutter 渲染器也能跑在 MCP 应用内，所以同一条信息流可以出现在支持 MCP 应用的助手里，例如 Claude 与 Gemini。

安全设计值得单独说。智能体不产出可直接执行的界面代码，只描述「要显示什么」；每个应用用自己的组件绘制，数据与子组件在服务端完成绑定，敏感数值不进入模型厂商口径。这同时解决了两件事：样式不会被模型带偏，以及财务数字不必经过上下文窗口。代价是应用方得自己实现渲染器——开源 SDK 把这件事的成本降下来了，但没降到零。

本报保留一个问号。官方博客写「1.0 已是现行版本」，企业控制台仍写 0.9.1，Android 渲染器还是 alpha公开报道。这三句话同时为真，说明「协议稳定」与「全平台稳定」不是一回事。读者若按 1.0 去排期，最好先确认自己走的是哪条路径；第 12 版把这类成本列得更细。

同一批公司这两天把智能体往两个方向塞：一头是团队内部的文档、表格与会议，一头是对外的品牌与购物。两边抢的是同一个东西——用户在哪个界面里做决定。公开报道

Anthropic 把 Claude 塞进协作物件。新增 Sheets、Whiteboards、Data 三类产物，团队可以不切应用就让 Claude 建表格、整理想法、做数据看板；交互式连接器把 Adobe、Atlassian 等伙伴应用嵌进 Claude，Salesforce、NetSuite、Workday 的插件（测试版）自带销售、财务与人力技能公开报道。Claude Meetings 被描述为「即将到来」：进会议做记录、把讨论写成计划并更新文档。另一家媒体则报道它已能现场听会、在白板上画时间线、实时拉取工作应用数据公开报道。两处口径不一致，本报按「部分可用、仍在限制中」记。

OpenAI 把品牌塞进 ChatGPT。Businesses in ChatGPT 允许企业认领资料、更新营业信息、提交带价格与库存的商品源、查看客户互动；符合条件的美国电商与在线服务商还可以上线 Business Agents，在对话里回答问题、帮用户逛商品公开报道。该功能目前是 beta。这不是加一个聊天入口，而是把「搜索—比较—下单」的界面搬进对话。谁定义那个界面，谁就离交易更近。

Google 与 Meta 在补外围。Gemini Intelligence 扩到更多设备类别；Meta 的 Muse 助手上了 Apple Watch 与 Wear OS，可用语音通话、短信或听写唤起；Reddit 用 AI 把上万件商品的好恶汇总成产品评论公开报道。这些都不改模型，改的是「在哪儿能碰到它」。

把这一版和第 03 版并排放，会看出一条分岔。A2UI 的路线是让智能体把界面交给应用画，应用保留样式与数据的控制权；办公与商业产品的路线是让智能体直接住进自家界面，用户不再离开。前者是协议，后者是阵地。两条路都承认同一件事：纯文字回答已经不够用了，但它俩对「谁拥有界面」给出了相反答案。这个分歧比任何一次跑分都更值得盯。

还有一处容易被忽略的默认值：微软把英国 Copilot 租户默认开放给 Claude 模型访问，管理员要在 12 月 9 日前复核设置，而数据处理在美国公开报道。「默认开」属于接口层的决定，不是模型层的；它把合规判断从「要不要接」改成了「有没有在截止日前关掉」。第 08 版接着讲这一层。

深读 · 四道闸拦住的不是恶意 来源 · 官方第 05 版 / 共 16 版

OpenRouter 在 11 月 12 日给 Agent SDK 加了一组防护，针对的是智能体最平常、也最烧钱的一种失败：反复调用一个失败的工具。模型并没有变坏，只是没有任何东西告诉它「可以停了」厂商口径。

先把这个失败讲清楚。工具报错、参数没改、模型再试一次——这是重试逻辑最自然的写法，问题在于每一轮都会把整段对话连同历史一起重发，于是下一轮比上一轮更贵。循环里没有退出条件，也没有预算概念；放着跑一夜，账单可能是四位数的美元公开报道。本报把它叫 死循环模型不断重复同一组工具调用且没有退出条件。它不需要任何恶意，只需要一个一直失败的工具和一个没有上限的循环。：它不需要模型有任何恶意，只需要一个一直失败的工具和一个不会自己停的循环。

官方给出的测试结果很短：在 6 个模型上测过，开启防护后模型在第三次重复调用被正确拦下，避免了意外的高额 API 支出厂商口径。本报没有独立复现这组数字，也不把它读成「所有循环都能拦住」——它说明的是这一组测试里的一种特定重复。官方同时说明，技术细节与推广计划尚未公布公开报道。四道闸的清单是公开的，闸的高度目前不是。

为什么这条值得放深读。过去一年，智能体出事的叙事都围着「越权」「越界」转，于是防护也多写在权限那一侧。但真实生产环境里最先烧掉预算的，往往是这种既不越权、也不恶意、只是停不下来的循环。把「停」做进 SDK，意味着责任从「让模型更聪明」转到「让调用层有边界」。这与第 03 版把界面交给应用画，是同一种思路：不指望权重解决问题，用代码把上限钉死。

还有一个容易被跳过的点：拦错了怎么办。四道闸里任何一道误判，都会把一个本来快完成的任务砍断。步数上限和成本上限尤其如此——它们可靠，正是因为它们粗暴。发布材料目前没有说明被拦截后是返回可恢复状态、还是直接终止，也没有说明误报如何观测公开报道。一道会误伤的闸，需要配套一条「怎么申诉」的路径；否则团队第一反应会是把它关掉。本报把这一条记进第 15 版的观察清单，等后续文档补上。

本期写到的更新几乎都不是「模型变强」，而是「模型怎么把结果交出来」。这类发布最容易在标题里被读成「已全面可用」，也最容易在升级时把账留给你。本报把它做成五个可以照着问的问题，不需要专业知识，只需要在排期之前问一遍。本版是本报自设的方法，不代表任何厂商口径。

第一问：变的是哪一层？是模型、协议、SDK、渲染器，还是默认值？A2UI 1.0 变的是协议，Android 渲染器没跟着变；LangChain 变的是运行环境要求，模型能力一点没动；微软把英国租户默认开放给 Claude，变的既不是模型也不是协议，只是一个开关的初始值。先定位层级，才知道该通知谁。

第二问：我走的这条路径，版本号是多少？「1.0 是现行版」和「你用的那条路径支持 1.0」不是一回事。企业注册处仍写着 0.9.1，Compose 渲染器还是 alpha。把博客里的版本号抄进排期表，是这类升级最常见的翻车方式；正确的做法是把自己实际依赖的组件逐个列出来，各记一个版本。

第三问：出错时，谁兜底、拦错了怎么办？四道闸解决的是「停不下来」，但它们也会带来「被误停」。问清三件事：拦截后返回什么状态、能否从断点继续、有没有误报的观测口径。只写「我们加了保护」而不写「保护误伤时怎么恢复」，等于把问题从账单挪到了可用性。

第四问：升级要改谁的代码，谁付这笔钱？把最低版本抬到 Python 3.11，成本落在每一条 CI 流水线上；把界面改成原生组件，成本落在应用前端；把云 API 搬进本地模拟器，反而是在替你省手续。同一份发布说明里，有的改动替你省钱，有的改动给你派活——把它们分开列，才知道该高兴还是该排期。

第五问：默认值有没有被悄悄改掉？「默认开」是最容易被漏掉的一种接口变更：没有新 API、没有新文档，但数据流向变了。英国 Copilot 租户那个 12 月 9 日的复核期限，就属于这一类。发布说明不写它，设置页里写着它；每期至少翻一次自己租户的默认开关。

工具链那一侧是另一种紧迫。Git 一次修了六个漏洞，波及递归克隆、引用处理、合并、二进制补丁与导入；任何自建 Git 服务或 CI 流水线的团队都该尽快打补丁公开报道。另有远程访问服务商 N-able 在研究者公布大量未修复漏洞后，建议自托管客户先把服务器下线公开报道。这两条都不是模型安全问题，但都长在智能体真正要跑的基础设施上。第 07 版那些本地工具越方便，这一层的补丁就越不能拖。

学术 · 从「解出来」到「证出来」 来源 · 第三方信息网第 09 版 / 共 16 版

研究侧这一批最能说明本期的边界：模型确实在往前走，但要变成能进生产环境的东西，仍得先穿过一层可核对的证据。形式化验证正是那层证据。

最硬的一条是形式化证明进了真实代码库。DeepMind 的 AlphaProof Code（内部代号 CodeMender）用智能体为真实软件生成数学证明，先攻密码学库；报道给出的规模是四周写下 650 万行形式化证明，并已完成 Signal 协议底层代码的安全验证厂商口径。另一路报道说，团队把人类密码学家与 AI 智能体配对，用于核对 Signal 的后量子握手与 Triple Ratchet 协议公开报道。它与「模型解出一道难题」的差别在于：证明可以被验证器逐行复核，不靠评分者的判断。

怀疑也来得很快。技术社区里有人质疑「把一个人类编写的非平凡库验证到零缺陷」这一说法，指出用 LLM 写 Lean 证明有一条很方便的作弊路径——把规约悄悄改弱，证明就变得容易了公开报道。本报不裁决这个争议，只把它记下来：形式化验证的可信度，最终落在「规约是谁写的、有没有被改过」上。这又是一个接口问题，不是模型问题。

生成式 UI / A2UI
智能体不只回文字，而是描述一张界面该有什么；由应用用自己的组件画出来。A2UI 是 Google 创建的开放协议。
渲染器
把界面描述变成真正可点控件的那层程序。网页用 React、Angular、Lit，移动端用 Flutter、SwiftUI 与 Jetpack Compose。
原生组件
应用自己写好的按钮、表单与图表，不是模型吐出的一段 HTML。样式与交互由应用负责，模型只给内容。
双向函数调用
界面上的控件可以反过来向智能体发起一次调用，例如选择器当场核查余位，而不必等人在文字里回复。
协议版本漂移
同一协议在博客、企业控制台、各平台渲染器上停在的版本号不一致。稳定版说的是协议，不等于每条路径都升完了。
死循环 / doom loop
模型不断重复同一组工具调用且没有退出条件。不需要恶意，只需要一个一直失败的工具和一个没有上限的循环。
步数与成本上限
给一次任务钉死「最多走几步、最多花多少钱」的两道闸。可靠是因为粗暴，代价是可能误伤快完成的任务。
本地模拟器
在本机复刻云服务接口的程序，让测试不必连真云。按服务给出保真度评分，说明「像不像」可以量化。
保真度
模拟器与真实服务行为一致的程度。按服务分别评分，意味着某些接口可放心本地测，另一些仍要上真云核。
端侧智能体
跑在手机或电脑本地的小模型，把请求转成工具调用而不上传个人数据。能力通常限于编排，不是通用对话。
工具调用 / tool call
模型不直接执行动作，而是输出「该调哪个工具、带什么参数」。执行与权限始终由应用掌握。
MCP 应用
跑在支持 MCP 的助手内部的小型界面。网页与 Flutter 渲染器都能在里面工作，同一条信息流可跨宿主显示。
兼容性账单
一次依赖或运行环境升级要改的东西：镜像、CI 矩阵、只旧版本验证过的插件。它是任务，不是机会。
形式化验证
